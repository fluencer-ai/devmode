## Independent review, round 1 (Codex, `pesado`)

The first fix parsed commands with `shlex`, which made R05 lose calls the old
raw regex used to catch. The reviewer showed each one against 8521603; all were
reproduced here before changing the code.

| # | Review finding | Verdict | What changed |
|---|---|---|---|
| R1 | A delete inside a heredoc fed to `bash` went from deny to allow | Accepted | R05 scans the raw text, heredoc bodies included |
| R2 | `xargs -0 rm -rf /` (and `timeout 5 rm -rf /`, found while checking) went from deny to allow | Accepted | the scan finds `rm` anywhere in a segment, after any wrapper |
| R3 | A `#` inside a word made `shlex` drop the rest of the line | Accepted | the raw scan has no comment handling to fool |
| R4 | `///` and `$HOME/*` went from deny to ask | Accepted | root targets are normalized (repeated `/`, trailing `/.`, wildcards over `~` and `$HOME`) |
| R5 | R07 let `.envrc.local`, `id_rsa.backup`, `secrets-production.yaml` through | Accepted | the secret-file rule covers dotenv variants, key copies and per-environment secret files |
| R6 | Operands after `--` were read as flags | Accepted | flags are read only before `--`; an rm call with no static operand asks |
| R7 | A directory literally named `~` or `*` (quoted) is denied | Rejected | deny is the safe side for a delete guard; nobody should need `rm -rf '~'` without a prompt |
| R8 | The report said the Codex fallback runs only when `guardrails.py` is missing | Accepted | wording fixed below |

New tests, each seen failing before the change:
`test_rm_rf_root_is_denied_however_the_call_is_wrapped`,
`test_rm_rf_with_targets_from_input_or_after_double_dash_asks`, and more
names in `test_write_guard_uses_the_secret_file_rule`. Trade-off made on
purpose: text that only mentions `rm -rf /` (an `echo`) is denied again, as in
8521603; a false positive is the safe side here.

## Residual risks (left open)

- **Codex fallback drift.** `codex_hooks.py` keeps a `_fallback_evaluate`
  with the v1 rules (including the split-flag gap of finding 1). It runs when
  no `guardrails.py` is found in `.claude/hooks/` or
  `integrations/conductor-beads/hooks/`, or when the one found cannot be
  imported or has no `evaluate`. `install.sh` copies `guardrails.py` to
  `.claude/hooks/` and the adapter to `.codex/hooks/`, so a normal install
  loads the real rules. Worth deleting or delegating in a later change.
- **Other delete commands.** `find ... -delete`, `git clean` without `-f`, and
  `rsync --delete` are out of R05's scope by design; the guard is a seatbelt,
  not a sandbox.
